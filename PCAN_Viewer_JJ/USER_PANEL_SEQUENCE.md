# 유저 패널 명령 시퀀스

R008 기준. 생성/편집 버튼과 명령어 뷰어 사이의 **명령어 / 응답 이름** 열에서 단계 이름을 입력합니다. 이름도 패널 Save에 저장됩니다.

EDIT 모드에서 **Add TX Tool → Widget Type: sequence → 명령 시퀀스 설정**을 선택합니다.
버튼과 로그가 함께 표시되므로 일반 버튼보다 넓은 영역(예: Row Span 8, Col Span 12)을 권장합니다.

설정창은 기본 CMD 한 줄로 시작합니다. 생성은 선택 행 아래에 삽입하고, 삭제 및 위로/아래로 버튼으로 순서를 편집합니다.

- **CMD:** 메인 패킷 생성창과 같은 DBC/HEX 입력, Classic/FD, BRS, 길이, CRC, 주기, Note 설정을 사용합니다. Extended ID도 직접 지정할 수 있습니다. Repeat 기본값은 1이며, 여러 번 송신하면 Cycle Time을 송신 간격으로 사용합니다. 마지막 송신 후 다음 단계로 이동합니다. Hyundai_CRC는 실행할 때 AliveCount와 CRC를 계산하며, 새 실행에서는 카운트를 처음부터 시작합니다.
- **RCV:** 동일한 편집창에서 비교할 신호 이름 왼쪽을 체크하고 기대값 및 timeout(ms)을 설정합니다. 한 프레임에서 선택한 모든 비트가 일치해야 성공합니다. 버스, ID, 표준/확장, Classic/FD, BRS, 데이터 길이도 일치해야 합니다. RCV는 CRC를 재계산하지 않으며 저장된 기대 비트를 비교합니다. 변하는 CRC/AliveCount는 비교 대상에서 제외할 수 있습니다.
- **DEL:** 0~600000ms 대기합니다.

실행 데이터는 바이트 배열과 RCV 비교 마스크로 저장합니다. 패널 파일을 다시 불러올 때 메인 DBC가 없어도 동작합니다. CMD는 HEX 또는 `0/1` 비트로 수정할 수 있습니다. RCV는 **비트 조건 보기 / 편집** 버튼에서 `[0]: XXXX XX01` 형식으로 수정합니다. 왼쪽이 bit 7이며 `X`는 비교 제외입니다. 다른 패킷 설정이나 timeout은 **패킷 생성 / 편집**에서 수정합니다.

RUN 모드에서 버튼을 누르면 시작하고, 다시 누르면 정지합니다. 재실행은 항상 첫 단계부터 시작합니다. 송신 실패·연결 해제·응답 타임아웃이면 오류 로그를 남기고 중단합니다. CMD 직후 들어온 응답은 바로 뒤 RCV에서 확인하며, 이전 실행의 응답이나 이미 처리한 응답을 다음 RCV에 재사용하지 않습니다.

버튼은 실행 전 파랑, CMD 청록, RCV 주황, DEL 보라, 정지 회색, 완료 녹색, 오류 빨강입니다. 로그는 일반 진행 검정, 오류 빨강, 전체 완료 녹색입니다. 우클릭 메뉴로 로그를 지울 수 있으며 최근 2000줄을 유지합니다.

로그는 패킷 바이트 대신 `[시간] 현재순번/전체개수 종류 BUS CAN_ID 이름 · 상태`를 표시합니다. 이름을 비워두면 `이름 없음`으로 표시됩니다. Standard ID는 `0x001`처럼 3자리, Extended ID는 `0x00000001`처럼 8자리이며 명령어 뷰어에도 같은 규칙을 적용합니다.

```text
[10:30:00.001] 1/3 CMD BUS_1 0x001 Init 명령 · 송신 완료
[10:30:00.125] 2/3 RCV BUS_1 0x00000001 Init 응답 · 응답 조건 일치
[10:30:00.126] 3/3 DEL - - 안정화 대기 · 200 ms 대기
```

패널을 닫거나 모드를 변경하면 패널의 모든 시퀀스·대기·버튼 누름 반복 송신·주기 송신을 중지합니다. RUN 복귀 시 자동 재개하지 않습니다. 이미 송신한 명령은 되돌리지 않습니다. 메인 TX 패널의 별도 송신은 이 중지 범위에 포함되지 않습니다.

여러 시퀀스와 기존 패널 송신은 독립적으로 실행됩니다. 같은 신호를 동시에 조작하는 구성은 사용자가 조정해야 합니다.
