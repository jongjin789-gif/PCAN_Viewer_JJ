## 1. 화면 구성

프로그램의 메인 화면은 크게 4개의 영역으로 구성됩니다.

- **① Connection Control**: CAN 하드웨어 채널을 선택하고 통신을 시작/종료하는 영역입니다.
- **② Database Files**: 통신 데이터를 해석하기 위한 `.dbc` 또는 `.sym` 파일을 로드하고 관리하는 영역입니다.
- **③ Monitoring Tree (수신부)**: CAN 버스에서 수신된 메시지와 시그널의 값을 실시간으로 보여주는 영역입니다.
- **④ Tx Panel (송신부)**: CAN 메시지를 생성하고 버스로 전송하는 패널입니다.

---

## 2. 기본 사용법

### 채널 연결
1.  **Connection Control** 패널에서 연결할 **Bus**를 선택합니다. (최대 3개 채널 동시 지원)
2.  사용할 CAN 하드웨어 채널과 통신 속도(Baudrate)를 선택합니다.
3.  **CAN FD** 통신인 경우, FD 옵션을 활성화하고 데이터 통신 속도(Data Baudrate)를 설정합니다.
4.  **Open** 버튼을 눌러 통신을 시작합니다. 연결에 성공하면 버튼이 비활성화되고 **Close** 버튼이 활성화됩니다.

### 데이터베이스(DBC/SYM) 적용
1.  **Database Files** 패널에서 해당 버스에 맞는 **Load DBC/SYM** 버튼을 클릭하여 파일을 선택합니다.
2.  파일이 성공적으로 로드되면 목록에 파일명이 표시됩니다.
3.  이제 수신부(Monitoring Tree)에서 CAN ID 대신 메시지 이름이 표시되고, 하위에 시그널들이 나타납니다.

> **💡 .sym 파일 호환성 정보**
> PEAK-System의 `.sym` 파일은 포맷 버전 5.0과 6.0을 모두 지원합니다. 프로그램이 파일 내용을 분석하여 버전을 자동으로 감지하고 파싱하므로 사용자는 확장자만 맞으면 자유롭게 로드할 수 있습니다.

### 데이터 수신 및 분석
-   **Monitoring Tree**에서는 수신된 메시지가 CAN ID를 기준으로 그룹화되어 표시됩니다.
-   DBC 파일이 적용된 경우, 메시지 이름과 그 하위의 시그널 목록이 트리 형태로 나타납니다.
-   **Value** 컬럼에서 메시지의 Raw Data(16진수) 또는 각 시그널의 물리 값(Physical Value)을 실시간으로 확인할 수 있습니다.
-   **Cycle (ms)** 과 **Count** 컬럼을 통해 메시지 수신 주기와 횟수를 파악할 수 있습니다.
-   **일괄 선택**: 메시지 이름(부모 항목)의 체크박스를 선택하면 하위의 모든 시그널이 한 번에 선택/해제됩니다.
-   **정렬**: 메시지 목록은 기본적으로 **Bus 번호 → CAN ID 순**으로 자동 정렬되어, 그래프를 열 때마다 항상 일관된 순서의 범례와 색상이 적용됩니다.

## 3. 송신 기능 (Tx Panel)

메인 창 하단의 송신 패널에서는 CAN 메시지를 직접 만들어 버스로 보낼 수 있습니다.

### 패킷 생성 및 수정
1.  **Create Packet** 버튼을 눌러 패킷 생성 창을 엽니다.
2.  **CAN ID / Symbol** 항목에서 DBC 파일에 정의된 심볼(메시지 이름)을 선택하거나, CAN ID를 직접 16진수로 입력할 수 있습니다.
    -   심볼을 선택하면 ID, Length, Type이 자동으로 채워지고 하단에 시그널 표가 나타납니다.
    -   시그널 표의 **Value** 셀에 원하는 물리 값을 입력하면, 상단의 **Data (HEX)** 가 자동으로 계산됩니다.
3.  **Data (HEX)** 필드에 직접 16진수 데이터를 입력할 수도 있습니다. 이 경우, 시그널 표의 값들이 반대로 자동 계산되어 표시됩니다.
4.  생성된 패킷을 수정하려면 목록에서 해당 항목을 **더블클릭**하세요.

### DBC 신호 CRC-8 / CRC-16
- DBC Signals의 **자동 증감 / CRC**에서 `CRC-8` 또는 `CRC-16`을 선택하고 옆 셀의 **CRC 설정** 버튼을 누릅니다. CRC-8은 8비트, CRC-16은 16비트 정수 신호에 적용합니다.
- 연산 범위는 **0부터 시작하는 바이트 번호와 사이즈**로 지정합니다. 예를 들어 2~31바이트는 시작 `2`, 사이즈 `30`입니다.
- **추가 연산 데이터**는 범위 뒤에 붙이는 고정 HEX 바이트입니다. `0x0000` 또는 `00 00`은 0인 바이트 두 개를 추가합니다. `12 34`는 입력 순서 그대로 붙습니다.
- `poly`, `init`, `xorout`은 HEX 값으로 입력합니다. Poly는 최상위 항을 제외한 정방향 다항식이며, RefIn/RefOut은 각각 입력 바이트/최종 CRC의 비트 반전을 지정합니다.
- 카운트 값 반영 후 매 전송마다 CRC를 계산합니다. 결과에는 Factor/Offset을 적용하지 않습니다. CRC-16은 설정창에서 **LSB 먼저 (Intel)** 또는 **MSB 먼저 (Motorola)**를 선택합니다. 예: `0x1234`의 결과는 각각 `34 12`, `12 34`입니다. DBC 신호의 비트 위치는 유지하며, 입력 데이터 순서와 RefIn/RefOut 설정은 영향을 받지 않습니다. 이전 저장 설정은 기존 DBC 순서를 유지합니다.
- 연산 범위에 CRC 신호 자신의 비트가 포함된 바이트가 하나라도 있으면 등록 오류를 표시합니다. 길이 초과, 잘못된 파라미터, CRC 간 순환 참조도 허용하지 않습니다.
- 설정은 패킷 편집, 자동 저장 파일 및 XMT 저장/불러오기에서 유지됩니다. 기존 `Hyundai_CRC` 패킷 타입 대신 DBC 신호 CRC를 사용할 때는 패킷 타입을 **적용 안함**으로 둡니다.

### 패킷 타입 (Hyundai_CRC)
-   **패킷 타입** 콤보박스에서 `Hyundai_CRC`를 선택할 수 있습니다.
-   이 타입을 선택하면, 사용자가 **Data (HEX)** 필드에 어떤 값을 입력하든 상관없이, 실제 패킷이 전송되는 시점에 프로그램이 내부적으로 아래 규칙에 따라 데이터의 앞 3바이트를 덮어씁니다.
    -   `Data[0]`, `Data[1]`: CRC-16 CCITT-FALSE 값 (Little Endian)
    -   `Data[2]`: 0~255까지 순환하는 Alive Counter 값
-   사용자는 CRC와 Alive Count를 제외한 실제 유저 데이터(3번 바이트부터)만 신경 써서 입력하면 됩니다.

### 패킷 전송 및 관리
-   **단발 전송**: 목록에서 전송할 패킷을 선택하고 키보드의 **스페이스바**를 누르면 1회 전송됩니다.
-   **주기 전송**:
    -   패킷 생성 시 **Cycle Time**을 0보다 큰 값(ms)으로 설정합니다.
    -   목록의 **Action** 컬럼에 있는 **Start** 버튼을 누르면 설정된 주기로 자동 전송이 시작됩니다.
    -   전송 중에는 버튼이 **Stop**으로 바뀌며, 클릭 시 전송을 멈출 수 있습니다.
-   **관리 단축키**:
    -   **삭제**: `Delete` 키
    -   **복사/붙여넣기**: `Ctrl+C`, `Ctrl+V` (여러 항목 동시 선택 가능)
-   **목록 저장/불러오기**: **Load/Save Tx List** 버튼을 통해 현재 패킷 목록을 `.xmt` 파일로 저장하거나 불러올 수 있습니다.

## 4. 실시간 그래프

수신부 트리에서 원하는 시그널을 선택하여 실시간으로 값이 변하는 모습을 그래프로 확인할 수 있습니다.

### 그래프 열기
1.  수신부(Monitoring Tree)에서 그래프로 보고 싶은 시그널 이름 앞의 **체크박스를 선택**합니다. (여러 개 선택 가능)
2.  **[View Real-time Graph for Selection]** 버튼을 클릭하면 선택된 모든 시그널이 하나의 그래프 창에 표시됩니다.

### 주요 기능
-   **범례 (Legend)**: 그래프 우측의 범례 항목을 **더블클릭**하면 해당 시그널의 그래프를 잠시 숨기거나 다시 표시할 수 있습니다.
-   **태그 (Tags)**:
    -   그래프 위의 특정 지점을 **클릭**하면 해당 위치의 시간과 값을 보여주는 태그가 고정됩니다.
    -   범례에서 여러 시그널을 선택(클릭 또는 Ctrl+클릭)한 상태로 그래프를 클릭하면, 선택된 모든 시그널에 대한 태그가 동시에 생성됩니다.
    -   생성된 태그를 다시 클릭하면 삭제됩니다.
-   **X축 동기화 (Sync X-Axis)**: 여러 개의 그래프 창을 열었을 때, 이 옵션을 체크하면 하나의 창에서 줌(Zoom)하거나 화면을 이동(Pan)할 때 다른 모든 동기화된 창의 X축이 함께 움직입니다. 창 크기를 조절해도 동일하게 적용됩니다.
-   **레이블/스타일 수정 (Edit Labels)**:
    -   그래프의 제목과 각 범례의 표시 이름을 사용자가 원하는 텍스트로 변경할 수 있습니다.
    -   범례 목록에서 원하는 항목을 **마우스로 드래그**하여 순서를 바꿀 수 있습니다.
    -   각 시그널의 **선 색상**과 **선 종류**(실선, 점선 등)를 직관적으로 변경할 수 있습니다.
-   **사용자 정의 수식 (Formula)**:
    -   **Formula** 버튼을 눌러 그래프에 표시된 시그널들을 변수(X1, X2...)로 사용하여 새로운 가상 시그널(Y1, Y2, Y3)을 만들 수 있습니다.
    -   예: `X1 + X2` 또는 `(X1 - 5) * 10` 과 같은 사칙연산을 지원합니다.
-   **스크린샷 (Screenshot)**: 현재 그래프 뷰를 이미지 파일(.png)으로 저장합니다. X축 동기화가 켜져 있으면 모든 동기화된 그래프를 하나의 긴 이미지로 합쳐서 저장합니다.

## 5. 로그 기록 및 뷰어

### 데이터 기록 (Record)
-   CAN 채널이 하나 이상 열려있는 상태에서 메인 창의 **Record** 버튼을 누르면 기록 창이 나타납니다.
-   이때부터 수신되는 모든 CAN 메시지는 PEAK-System의 `.trc` 포맷으로 기록됩니다.
-   기록 창을 닫거나 **Save** 버튼을 누르면 로그 파일이 저장됩니다. (기본 저장 경로: `[프로그램 폴더]/Log/`)

### 로그 뷰어 (Log Viewer)
-   **Open TRC Log Viewer** 버튼을 클릭하여 저장된 `.trc` 파일을 엽니다.
-   로그 뷰어는 파일을 열 때 **메인 창에 현재 로드된 DBC/SYM 파일**을 기준으로 로그를 해석하여 분석 결과를 보여줍니다.

#### 로그 뷰어 기능
-   **DBC 탭**:
    -   로그 파일에서 발견된 메시지 및 시그널 목록을 보여줍니다.
    -   여기서 시그널을 체크하고 **View Graph** 버튼을 누르면, 로그 전체 기간에 대한 **정적 그래프**를 볼 수 있습니다. (실시간 그래프와 기능 동일)
-   **LOG 탭**:
    -   `.trc` 파일의 원본 내용을 표 형태로 보여줍니다.
    -   **필터**: 시작·끝 CAN ID를 16진수로 입력하고 필터를 켭니다. `0x000~0x1FFFFFFF` 범위로 Standard와 Extended를 모두 지원합니다. 같은 ID만 보려면 시작·끝을 같게 입력합니다.
    -   **Save**: 현재 필터 결과를 별도 `.trc` 파일로 저장합니다. 원본 헤더·시간·타입·방향·데이터·줄바꿈은 유지하고 메시지 번호만 1부터 다시 매깁니다. 원본과 다른 파일명을 사용해야 합니다. 필터가 꺼져 있으면 전체 표시 로그를 저장합니다.
    -   **로그 데이터 재전송**:
        -   **전송** 버튼: 현재 필터 결과만 원래 시간 간격으로 재전송합니다. 표시된 선택 행이 있으면 그 위치부터 시작하며, 없으면 첫 결과부터 시작합니다. 송신을 시작하면 대상 목록이 고정됩니다.
        -   **선택 전송** (또는 스페이스바): 표에서 선택한 한 줄의 데이터만 1회 전송합니다.
        -   **반복** 체크박스: 전송이 끝나면 필터 결과의 처음부터 다시 반복합니다.

## 6. 사용자 패널 (User Panel)

Tx Panel 툴바의 **User Panel** 버튼으로 여는 사용자 정의 조작/표시 화면입니다.

### 제어 모드
- **EDIT**: 도구 생성/삭제/배치/설정 변경 모드
- **STANDARD**: 유저 패널 TX 전체 정지, RX 표시 위젯 갱신 모드
- **RUN**: TX/RX 모두 동작
- 편집 보안이 활성화된 경우(STANDARD/RUN -> EDIT 복귀 시) 비밀번호 입력이 필요합니다.
- 패널 닫기 또는 모드 변경 시 패널의 주기 송신·시퀀스·응답 대기·지연을 모두 중지합니다. RUN 진입 시 등록 패킷의 주기 전송은 첫 조작 없이 시작하며, 시퀀스는 실행 버튼으로 시작합니다. 메인 TX 패널의 별도 송신은 이 중지 범위에 포함되지 않습니다.

### TX 패킷 등록
- EDIT 모드의 **TX 패킷 등록 / 관리**에서 메인창과 같은 패킷 생성창으로 등록·수정·삭제합니다. 카운트 업/다운/순환, CRC-8/CRC-16 및 Hyundai CRC 설정을 지원합니다.
- **딜레이 입력은 필수**입니다. `0`은 도구 값이 바뀔 때만 전송하며, 양수는 해당 ms마다 패킷을 전송합니다. 주기 패킷은 연결된 도구가 없어도 RUN에서 전송합니다.
- 같은 BUS·ID는 한 번만 등록합니다. 연결된 도구가 있는 패킷을 삭제하려면 먼저 도구를 삭제하거나 다른 등록 패킷에 연결합니다.
- 전송 데이터 적용 순서: **등록 원본 → 도구 신호의 지정 비트 덮어쓰기 → 활성 카운트 → 활성 CRC**. 도구가 지정하지 않은 비트는 원본을 유지합니다.
- 등록 목록은 패널 JSON 및 패키지에 저장됩니다. 파일을 불러오면 EDIT에서 시작합니다. 기존 파일의 미등록 TX 도구는 패킷 등록과 연결을 완료해야 RUN을 사용할 수 있습니다. RX 도구는 기존 DBC 전체 선택 방식을 유지합니다.
- 카운트/신호 CRC를 사용하는 패킷은 해당 DBC/SYM이 필요합니다.

### 도구 생성
- **Add TX Tool**: 등록한 패킷의 ID/심볼로 송신 위젯 생성
- **Add RX Tool**: 수신 위젯 생성
- **Add Group/Shape**: 그룹/탭/도형 도구 생성
- 도형 빠른 생성: **Draw Rect / Draw Line**

### TX 동작
- **button**: 누르면 `Button Push Value`, 떼면 `Button Pull Value`를 패킷의 지정 비트에 반영합니다. 전송 간격은 등록 패킷의 딜레이를 따릅니다.
- **toggle**: ON/OFF에 따라 `Toggle ON/OFF Value` 송신
- 같은 버스·CAN ID·비트 영역에 연결한 토글은 하나를 켜면 나머지가 해제됩니다. 자동 해제된 토글의 OFF 값은 송신하지 않습니다. 켜진 토글을 다시 클릭하면 자신의 OFF 값을 송신합니다.
- **slider/spinbox**: `Min/Max/Resolution` 기반 값 송신
- **slider**: 정수형 신호(정수 scale/offset) 또는 정수 Resolution은 정수로 표시합니다. 나머지는 Resolution 자릿수에 맞춰 `0.1 → 1.0`, `0.01 → 1.00`처럼 표시합니다. `Initial Value (Home)`는 초기 위치이며, 왼쪽 Home 버튼은 슬라이더·값 표시의 두 행을 차지합니다. RUN에서 Home을 누르면 해당 값도 송신합니다. 초기 위치는 범위와 이동 단계에 맞춰 적용됩니다.
- **프레임 형식·길이·BRS·딜레이**는 등록 패킷에서 설정합니다. 도구별 TX Cycle Mode / TX Cycle 입력은 제거되었습니다.
- 단일 속성은 등록 패킷과 신호/비트 필드를 선택합니다. 멀티 공통 속성의 **TX 등록 패킷**으로 연결을 일괄 변경할 수 있습니다. RX BUS와 공통 배치·크기·BUS 속도 변경은 유지됩니다.

### 명령 시퀀스

**RUN Init 시퀀스 설정**에서 RUN 진입 시 자동 실행할 순서를 등록합니다. Init은 `CMD` 송신, `DEL` 대기, `START` 주기 시작, `STOP` 주기 정지만 지원하며 수신 비교는 없습니다. 목록을 비우면 Init을 사용하지 않습니다.

- RUN 진입 → Init 실행 → 성공 후 등록 주기 전송 시작 순서입니다. Init이 없으면 바로 등록 주기 전송을 시작합니다.
- Init 동안 일반 TX 도구/시퀀스 조작과 자동 주기 전송을 보류합니다. Init의 CMD는 실행되며, START/STOP으로 정한 주기 전송 상태는 Init 완료 후 적용됩니다.
- Init에서 STOP한 패킷은 자동으로 재시작하지 않습니다. 일반 시퀀스의 START로 다시 시작할 수 있습니다. Init 실패/중단 시 STANDARD로 돌아갑니다.
- RUN에 다시 진입하면 Init을 처음부터 실행합니다. Init과 실패 처리 설정은 패널 JSON/패키지에 함께 저장됩니다.

`Add TX Tool → sequence → 명령 시퀀스 설정`에서 생성합니다. 버튼과 로그를 보려면 Row Span 8, Col Span 12 정도의 영역을 권장합니다.

- 그리드 열: 종류(CMD/RCV/DEL/START/STOP), 패킷 생성/편집 또는 대상 선택, 명령어/응답 이름, 읽기 전용 요약 또는 비트 편집 버튼.
- 생성은 선택 행 아래에 삽입합니다. 삭제 및 위로/아래로 버튼으로 단계를 관리합니다.
- CMD: 등록한 TX 패킷을 선택하고 반복 횟수를 지정합니다. 도구 값과 카운트·CRC를 반영하는 공통 전송 처리를 사용하며, 반복 간격은 등록 패킷 딜레이를 따릅니다.
- RCV: 동일 ID의 신호를 하나 이상 체크하여 기대값을 설정하거나, DBC 없이 `[0]: XXXX XX01` 비트를 편집합니다. `X`는 비교 제외이며, 같은 프레임에서 모든 비교 비트와 버스·ID·형식·길이가 일치해야 합니다. 제한 시간(ms)을 넘기면 중단합니다.
- DEL: 설정 시간(ms) 후 다음 단계로 이동합니다.
- START/STOP: 등록 패킷 개별 또는 전체의 **자동 주기 전송**을 시작/정지합니다. 같은 패킷의 CMD 송신과 딜레이 0 도구의 값 변경 송신은 유지됩니다. START를 반복해도 타이머가 중복 생성되지 않습니다.
- 일반 시퀀스는 수신 조건 일치 시 OK, 수신 타임아웃/송신 오류 등 발생 시 NG로 표시합니다. 불일치 프레임은 제한 시간 동안 계속 기다립니다.
- **실패 시 실행할 명령 설정**에 CMD/DEL/START/STOP 목록을 입력할 수 있습니다. 실패하면 정상 단계 진행을 중단하고 해당 목록을 한 번 실행합니다. 실패 처리에 성공해도 원래 시퀀스 결과는 NG이며, 실패 처리 자체가 실패하면 즉시 종료합니다.
- 사용자의 정지, STANDARD/EDIT 전환, 패널 닫기는 실패 처리 목록을 실행하지 않고 모든 시퀀스 동작을 취소합니다.
- CMD는 등록 패킷을 참조합니다. RCV는 기대 바이트와 비교 마스크로 저장하며 기존 `X/0/1` 편집을 유지합니다.
- 버튼 클릭은 실행 → 정지 → 처음부터 재실행입니다. 일반 로그는 검정, 오류는 빨강, 전체 완료는 녹색입니다. 버튼은 실행 전 파랑, 송신 청록, 응답 대기 주황, 지연 보라, 정지 회색, 완료 녹색, 오류 빨강입니다.
- 로그에는 패킷 바이트 대신 이름을 표시합니다. ID는 Standard 3자리, Extended 8자리입니다.

```text
[10:30:00.001] 1/3 CMD BUS_1 0x001 Init 명령 · 송신 완료
[10:30:00.125] 2/3 RCV BUS_1 0x00000001 Init 응답 · 응답 조건 일치
[10:30:00.126] 3/3 DEL - - 안정화 대기 · 200 ms 대기
```

상세 실행 규칙은 [시퀀스 사용법](USER_PANEL_SEQUENCE.md)을 참고하세요.

### RX 동작
- **progress / label / status_lamp** 위젯 지원
- **status_lamp**: ON/OFF 조건을 독립 설정
- 조건 연산자: `gt`, `ge`, `lt`, `le`, `eq`, `ne`, `between`, `outside`

### CAN 없는 환경 테스트 (RX Simulator)
- **Apply Selected RX**: 선택 RX 도구에 수동 값 주입
- **Apply All RX**: 모든 RX 도구에 동일 값 주입
- **Auto Sim**: STANDBY/RUN 모드에서 자동 파형 값 주입

### 배치/그룹 편집
- **Tool List**에서 선택/우클릭(Edit/Delete/Z-order)
- **Bring Front / Send Back / Forward / Backward**: 전후 배치 순서 변경
- 도구 프레임 드래그로 이동, 우하단 드래그로 크기(span) 변경
- 오른쪽 **Tool Properties**: 도구를 선택하거나 **Edit**를 누르면 별도 창 없이 위치·크기·CAN·DBC·신호·값/동작을 편집합니다. 수정 후 **Apply Properties**를 누릅니다. 다른 도구를 선택하기 전에 적용해야 합니다.
- 생성은 기존 설정창을 사용합니다. 시퀀스의 단계·패킷·비트 상세 편집은 속성창 내부에서 열리며, 상세 편집의 OK 후 **Apply Properties**로 도구에 반영합니다.
- Tool List에서 **Ctrl+클릭 / Shift+클릭**, 캔버스의 프레임·제목에서 **Ctrl+클릭**으로 여러 도구를 선택합니다. 다른 값은 `(Mixed)`로 표시됩니다.
- 다중 선택에서는 변경할 항목만 체크하고 **Apply Checked Properties**를 누릅니다. 위치·크기·CAN BUS·일반 도구의 TX 주기/프레임 형식/BRS를 일괄 적용하며, 체크하지 않은 항목은 유지합니다. 시퀀스의 CAN BUS 변경은 포함된 CMD/RCV 패킷에 적용됩니다.
- **CAN BUS Speed**에서 nominal bitrate와 FD data bitrate를 변경할 수 있습니다. 속도는 같은 BUS의 모든 도구가 공유하며, 해당 BUS를 연결 해제한 뒤 적용해야 합니다. 메인창의 연결 속도 설정에도 반영됩니다. 패널 파일의 저장 속도는 불러오기만으로 장비에 적용하지 않으며, 체크 후 적용합니다.
- 그룹/탭 위로 드롭하면 자동으로 해당 부모에 편입
- 격자 한 칸은 기본 최소 32×32입니다. 작은 창에서는 스크롤로 보고, 큰 창에서는 격자와 도구가 표시 영역에 맞춰 확대됩니다.
- 일반 도구 최소 Row Span은 2, Col Span은 4입니다. 선 도형은 1을 허용합니다.

### 실행 취소 / 다시 실행

- EDIT 모드에서 **Ctrl+Z**로 실행 취소, **Ctrl+Y**로 다시 실행합니다. Edit 메뉴의 Undo/Redo에도 현재 가능한 횟수가 표시됩니다.
- 생성·삭제·위치·크기·전후 순서·적용한 도구 속성(시퀀스 설정 포함)을 최대 **50단계** 보관합니다. 다중 삭제와 속성 일괄 적용은 각각 한 단계이며, 생성창의 미리보기는 생성 확정 시 한 단계로 묶습니다.
- 실행 취소 후 새 작업을 적용하면 다시 실행 이력은 지워집니다. 패널 파일을 불러오거나 창을 닫으면 이력이 초기화되며, 파일에 이력은 저장하지 않습니다.
- CAN 송신·수신, 장비 연결 상태, BUS 실제 통신 속도는 되돌리지 않습니다. 통신 속도는 CAN BUS Speed에서 별도로 변경합니다.
- 속성 입력란에서 Ctrl+Z는 입력 중인 글자를 되돌립니다. 패널 작업을 되돌리려면 캔버스/도구 목록에 포커스를 두거나 Edit 메뉴를 사용합니다.

### 충돌 점검
- **Check TX Overlap**: 동일 CAN 프레임의 비트 오버랩 점검
- 오버랩 도구는 Tool List에서 빨간색으로 표시
- **Focus Conflict** 또는 항목 더블클릭으로 충돌 도구 간 이동

### 저장/불러오기
- 패널 설정 저장: `*.upp.json`
- **Save**에 시퀀스 순서·이름·패킷·비교 마스크·타임아웃·지연·반복 설정도 포함됩니다. 로그와 실행 진행 상태는 저장하지 않습니다.
- 패널 패키지 저장: `*.pjjupkg`
  - 패널 도구 설정 + Bus별 DB 파일(dbc/sym) 묶음 저장
  - 패키지 로드 시 기존 DB 목록을 교체 후 패널 복원

### DBC 없이 신호 편집

- Start Bit, Bit Length, Byte Order, Scale, Offset, Signed 설정을 패널에 저장합니다. DBC가 없어도 이 정보를 사용해 값을 송수신합니다. Intel(little-endian)과 Motorola(big-endian)의 정수 신호를 지원합니다.
- DBC Message/Signal을 선택하면 Start Bit와 Length 등을 자동으로 입력합니다. 두 항목은 DBC를 사용하는 동안에도 표시하고 수정할 수 있습니다.
- 저장된 비트 정보와 현재 BUS·CAN ID·Byte Order에 맞는 신호가 있으면 DBC 신호를 연결합니다. DBC가 없거나 변경되어 일치하지 않으면 **Unknown (Manual)**로 표시하고 저장된 비트 정보는 유지합니다.
- Start Bit/Length를 직접 수정하면 신호를 다시 매칭합니다. 같은 위치를 공유하는 신호가 여러 개이고 기존 선택으로 구별할 수 없으면 Unknown으로 표시하며, 원하는 신호를 직접 선택할 수 있습니다.
- 패킷 길이를 벗어나는 비트 범위, 잘못된 CAN ID/프레임 길이, Scale 0은 적용하지 않습니다.

## 7. 실행·빌드 및 버전

소스 폴더는 `PCAN_Viewer_JJ_R007`이며 버전은 `build_exe.py`의 `APP_VERSION = "R008"`로 지정합니다.

- 소스 실행: 의존성 설치 및 가상환경 활성화 후 `python main.py`. 버전 변경은 재실행 시 반영됩니다.
- 빌드: 같은 환경에서 `python build_exe.py`.
- Windows 실행 파일: `dist/PCAN_Viewer_JJ_R008_win/PCAN_Viewer_JJ_R008_win.exe`.
- Linux 바이너리: `dist/PCAN_Viewer_JJ_R008_linux/PCAN_Viewer_JJ_R008_linux`.
- EXE 제목은 파일명에서 버전을 읽습니다. 소스 수정 후 기존 EXE는 바뀌지 않으므로 새로 빌드한 R008 파일을 실행해야 합니다.
- 배포 폴더에 사용자 매뉴얼·시퀀스 사용법·변경 내역·OS별 실행 안내가 함께 복사됩니다.
- 기본 글꼴은 Consolas입니다. 설치되지 않은 환경과 지원하지 않는 한글 등은 시스템 대체 글꼴이 표시될 수 있습니다.
- 개발 테스트는 Python 3.13에서 `python -B -m unittest discover -s tests`로 수행합니다. 실제 CAN 장비와 빌드 결과의 동작 확인은 별도로 수행합니다.
